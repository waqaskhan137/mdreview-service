### E1 — I reported "the extension cannot deliver key presses" too early (#254)
Single tool calls delivered ZERO keydown events, and I filed #254 and parked #183 on that basis.
Both were correct as far as they went, but the conclusion was too broad: batching the actions in
ONE browser_batch round trip DOES deliver real keys, reproducibly (3/3), and with it I verified
every criterion that had been parked. The park was honest; the diagnosis was incomplete. Same
lesson as 2026-07-28's viewport claim: "I tried and it did not work" is a statement about my
approach, not about the tool.


### E2 — I documented a route as "4/4 reproducible" and it failed 3/3 on the next window
The successes were real (palette opened, focus moved to #cmdq, ? sheet rendered all seven
bindings). But they were a burst inside one window state I cannot reproduce on demand, and I wrote
the doc as though the recipe were reliable. Stage 8 for this very ticket is what caught it: the
rule "docs-only tickets still need their claims exercised" did exactly the work it exists to do.
Corrected in 571aacb to necessary-but-not-sufficient, intermittent, bounded retry then park.
**Falsified if:** the OS-frontmost hypothesis is confirmed and the route becomes deterministic
given that precondition — in which case the doc should state the precondition, not the shrug.


### E3 — I shipped a vacuous check in #183 and mutation-tested it wrong
The "palette goes full-screen at <=720px" case greps the CSS TEXT for `100vw`. It has been green
since #183 merged, while the rendered panel was 574x176 at 606px and never full-screen, because
the media block styles the transparent wrapper instead of the visible panel. My mutation tests
proved the check noticed the CSS TEXT changing; they never proved the CSS produced the intended
RESULT. That is the same defect class as #222's constructed KeyboardEvent, committed by me on the
same day I wrote the rule against it. Split to #265, whose AC forbids a text-regex check.
**Falsified if:** a text assertion can be shown to imply the rendered outcome — it cannot here,
which is the whole point.
